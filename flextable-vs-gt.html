Shared summary · 77 lines · R
# Data value -> column key (order = column order). Total is a copy of all subjects.
arm_cols <- c("Xanomeline High Dose" = "dose_a",
              "Xanomeline Low Dose"  = "dose_b",
              "Placebo"              = "control",
              "Total"                = "total")

anl <- bind_rows(adsl, mutate(adsl, TRT01A = "Total")) |>
  mutate(TRT = factor(arm_cols[TRT01A], levels = arm_cols))

big_n <- count(anl, TRT, name = "N")

# n (%) for every listed category, including those with 0 subjects
n_pct <- function(data, var, lvls) {
  data |>
    mutate(label = factor(.data[[var]], levels = names(lvls), labels = lvls)) |>
    filter(!is.na(label)) |>
    count(TRT, label, .drop = FALSE) |>
    left_join(big_n, by = "TRT") |>
    transmute(TRT, label = as.character(label),
              value = if_else(n == 0, "0", sprintf("%d (%.1f)", n, 100 * n / N)))
}

# Mean (SD) and Median (min, max)
mean_median <- function(data, var) {
  data |>
    summarise(
      .by = TRT,
      `Mean (SD)`         = sprintf("%.1f (%.2f)", mean(.data[[var]]), sd(.data[[var]])),
      `Median (min, max)` = sprintf("%.1f (%.0f, %.0f)", median(.data[[var]]),
                                    min(.data[[var]]), max(.data[[var]]))
    ) |>
    pivot_longer(-TRT, names_to = "label", values_to = "value")
}

demog <- bind_rows(
  "Sex, n (%)"                               = n_pct(anl, "SEX", sex_lvls),
  "Age, years"                               = mean_median(anl, "AGE"),
  "Age groups (years), n (%)"                = n_pct(anl, "AGEGR1", age_lvls),
  "Race, n (%)"                              = n_pct(anl, "RACE", race_lvls),

04

Two methods, same table

Method 1 · imperative

flextable

about 25 lines

as_grouped_data() turns block into section header rows. After that, styling is a chain of verbs, and each verb takes a part (header, body or footer) and optional i/j row and column selectors.

flextable · 28 lines · R
thin <- fp_border(color = "black", width = 1)

ft <- demog |>
  as_grouped_data(groups = "block") |>
  as_flextable(hide_grouplabel = TRUE) |>
  set_header_labels(values = c(label = "Characteristic", col_labels)) |>
  add_header_lines(title) |>
  add_footer_lines(footnotes) |>
  # fonts
  font(fontname = "Arial", part = "all") |>
  fontsize(size = 9, part = "all") |>
  fontsize(size = 8, part = "footer") |>
  bold(part = "header") |>
  # alignment
  align(j = 1, align = "left", part = "all") |>
  align(j = -1, align = "right", part = "all") |>
  valign(valign = "bottom", part = "header") |>
  # borders: under the title, under the column labels, after every block
  border_remove() |>
  hline(i = 1, border = thin, part = "header") |>
  hline_bottom(border = thin, part = "header") |>
  hline(i = ~ lead(!is.na(block), default = TRUE), border = thin, part = "body") |>
  # spacing: compact rows, indent the detail rows
  padding(padding.top = 0, padding.bottom = 0, part = "all") |>
  padding(i = ~ !is.na(label), j = 1, padding.left = 15, part = "body") |>
  set_table_properties(width = 1, layout = "autofit")

Method 2 · declarative

gt

about 45 lines

gt is told what the columns mean. groupname_col makes the section rows, rowname_col makes the indented stub, and the look is set through tab_options() and tab_style().

gt · 46 lines · R
gt_tbl <- demog |>
  gt(groupname_col = "block", rowname_col = "label") |>
  tab_header(title = title) |>
  tab_stubhead(label = "Characteristic") |>
  cols_label(.list = map(col_labels, \(x) html(gsub("\n", "<br>", x)))) |>
  cols_align(align = "right", columns = -label) |>
  tab_stub_indent(rows = everything(), indent = 4) |>
  tab_source_note(html(paste(footnotes, collapse = "<br>"))) |>

    style     = cell_text(weight = "bold", v_align = "bottom"),

05

Which one is better to code?

The two programs produce the same table, but they are organised very differently. The flextable code is about 25 lines and the gt code about 45.

Aspectflextablegt
Mental model
flextableImperative: "make row i, column j of part p look like this." Close to SAS PROC REPORT compute blocks.
gtDeclarative: "this column is the stub, this one is the group." The layout follows from what the columns mean.
Section header rows
flextableas_grouped_data(), then target rows with formulas such as i = ~ lead(!is.na(block))
gtBuilt in: groupname_col = "block"
Indenting detail rows
flextableManual padding on the selected rows
gttab_stub_indent()
Borders
flextableExplicit border_remove() + hline() calls. You can see exactly which line goes where.
gtAbout 15 tab_options() border settings, mostly to turn off gt's default lines
Column widths
flextableAutofit to content out of the box
gtSplits the width evenly, so the stub needs whitespace = "nowrap" to stop labels wrapping
Multi-line headers
flextablePlain "\n" in the label
gtNeeds HTML (<br>) and html(), which shows gt is HTML-first
Footnotes
flextableadd_footer_lines(footnotes) takes a vector
gtOne tab_source_note() per note, or join them yourself
Word / RTF output
flextableNative and complete (save_as_docx(), save_as_rtf()), so it is submission-ready
gtgtsave() can write .docx/.rtf, but some styling is lost. HTML/PDF is its strength.
Web output
flextableGood
gtExcellent (interactive options, nanoplots, themes)

Verdict

  1. gt has the better-structured code. The table's structure (groups, stub, column labels) is declared once, and you never count rows. If you add a block to demog, the table updates by itself.
  2. flextable is easier to reason about cell by cell, and it is the one you can submit: the same ft object goes straight to Word and RTF with every border and indent intact.
  3. A practical split for clinical reporting: use flextable for anything that goes into a CSR or regulatory submission, and gt for HTML reports, dashboards and the web.
